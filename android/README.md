# Песенник для Android

Нативное приложение Kotlin для Android 7.0+, без WebView, Service Worker, рекламных и аналитических SDK. Установка — подписанным APK из GitHub Releases. Сайт/PWA продолжает работать независимо.

## Интернет только по кнопке

В APK вложен полный сборник. Запуск, поиск, чтение, поворот экрана и возвращение из фона не создают сетевых запросов. `ManualNetwork` создаётся только обработчиком кнопки «Обновить сборник» или подтверждения «Скачать» в диалоге новой версии. Запросы идут по HTTPS; фоновые службы, планировщики, автоповторы, телеметрия и облачное резервирование отсутствуют. При уходе приложения в фон соединение закрывается и задача отменяется. Возврат не возобновляет загрузку.

По кнопке сначала скачивается и проверяется `https://pesn.wef2000.ru/catalog.json`; снимок сохраняется через `AtomicFile`. Затем читается `https://pesn.wef2000.ru/android-update.json`. Ошибка одного этапа не блокирует второй. Повреждённые или недокачанные данные не заменяют прежний сборник. Шрифт и скорости хранятся отдельно, по постоянным идентификаторам песен.

Метаданные APK: `versionCode` (положительное целое), `versionName`, `apkUrl` (APK из Releases champigon/pesn), `sha256` (64 строчных шестнадцатеричных символа). APK предлагается только при большем `versionCode`; скачивается после подтверждения. Проверяются SHA-256, имя пакета, версия и совпадение подписи с установленным приложением. Далее открывается системный установщик с подтверждением Android. Разрешение на установку выдаёт сам пользователь. Технические соединения системы Android и её установщика не входят в сетевую работу Песенника.

## Сборка и подпись

Требуются JDK 17, Gradle 8.11.1, Android SDK Platform 35 и Build Tools 35.0.0. Ключи и пароли запрещено размещать в репозитории, GitHub Issues, Release assets или публичных артефактах.

1. Обновить исходники из GitHub и проверить песни: `node --test`.
2. Выполнить `node scripts/build.mjs`, затем `node scripts/android-assets.mjs`: эти команды включают текущие песни в APK. На телефоне при этом нет автоматической первой загрузки.
3. Выполнить `gradle -p android testDebugUnitTest lintRelease assembleRelease`.
4. На Windows задать `JAVA_HOME`, `ANDROID_HOME` и выполнить `./scripts/build-android.ps1`. Скрипт создаёт постоянный ключ при первой сборке вне репозитория, сохраняет локальную резервную копию, подписывает APK и проверяет подпись. Следующие сборки используют тот же ключ. Сохраните дополнительную копию приватной папки на отдельном носителе: потерянный ключ нельзя восстановить из APK.
5. Опубликовать `outputs/android/ВЕРСИЯ/pesennik.apk` и `SHA256SUMS` в GitHub Releases с тегом `android-vВЕРСИЯ`.
6. Только после публикации APK скопировать соответствующий `android-update.json` в `web/` и дождаться публикации Pages. Не менять `sha256` вручную.

Для новой версии увеличить `versionCode` и `versionName` в `app/build.gradle.kts`. Изменение песен не требует нового APK — достаточно привычного редактирования `songs/` и обновления по кнопке. Установка нового APK поверх старого сохраняет данные. Удаление приложения удаляет его локальные настройки; данные PWA автоматически не переносятся.

## Проверки

`gradle -p android testDebugUnitTest lintRelease` проверяет формат сборника, атомарную замену, ошибки хранения, жесты/таймер прокрутки, плотность экрана, адреса обновления, отмену и отсутствие автоповторов. `connectedDebugAndroidTest` проверяет запуск, поиск, чтение, удержание экрана, сохранение настроек, пересоздание и сворачивание Activity, число соединений и трафик UID. GitHub Actions выполняет эти проверки на эмуляторе с отключённым интернетом и сохраняет снимки интерфейса.

На физическом телефоне дополнительно проверить установку, ручную прокрутку с инерцией, крупный системный шрифт, поворот экрана и удержание экрана дольше системного тайм-аута.
